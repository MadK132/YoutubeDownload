# Техническое задание: iOS Video Downloader

> Уточнённое требование пользователя: приложение самостоятельно скачивает публичные YouTube и VK Видео на iPhone. Компьютер нужен только для разработки, сборки и первоначальной установки. Постоянный ПК, локальный или облачный сервис для скачивания не допускаются. Прежняя схема с сервисом на ПК отменена. DRM и обход авторизации не реализуются.

### Дополнение: плеер и загрузка YouTube/VK

- Открывать плеер выбранного ролика, показывать реальные доступные качества до 1080p.
- Получать файл по исходному ID, не по рекламным сетевым запросам. Сверять ID в ответе источника; отклонять подмену другим роликом и плейлисты.
- При распознанной рекламе нативного плеера временно отключать кнопку скачивания. Универсальное распознавание рекламы не обещается; вшитые интеграции не вырезаются.
- Скачивать дорожки напрямую на iPhone. Раздельные видео и звук собирать в MP4 через AVFoundation на устройстве. Для обработки параметров плеера YouTube использовать JavaScriptCore и YouTube.js. Не использовать FFmpeg или yt-dlp на внешнем ПК.
- Собирать нативный модуль в standalone IPA или development build. Expo Go не обязан поддерживать пользовательский модуль; ясно сообщать об этом при запуске в Expo Go.
- Веб-версия служит для проверки интерфейса и просмотра плееров. Автономная загрузка YouTube/VK выполняется в установленном приложении; прямые MP4/MOV могут скачиваться в браузере при доступном CORS.

## 1. Цель проекта

Разработать собственное iOS-приложение для загрузки видео из интернета с приоритетом удобства работы с видеоссылками.

Приложение предназначено для личного использования, без публикации в App Store и без платных сервисов.

Основные требования:
- Поддержка iPhone.
- Разработка на Windows.
- Бесплатные инструменты и библиотеки.
- Возможность установки приложения без App Store.
- Поддержка качества видео до 1080p.
- Современный минималистичный интерфейс.

Важно: не реализовывать обход DRM, авторизации или закрытого доступа. Поддерживать доступные без входа ролики YouTube/VK и прямые видеоссылки. Сохранять только контент, на загрузку которого у пользователя есть разрешение.

## 2. Технологический стек

Frontend:
- React Native.
- Expo.
- TypeScript.
- Expo Router.

Основные библиотеки:
- expo-file-system — работа с файлами.

## 3. Основной функционал

### 3.1. Главный экран

Создать современный интерфейс с:
- Полем для вставки URL.
- Кнопкой Paste.
- Кнопкой Download.
- Отображением названия видео и обложки, если метаданные доступны.
- Выбором качества.
- Отображением поддерживаемого формата.
- Индикацией ошибок.

Автоматически обнаруживать ссылку в буфере обмена при открытии приложения, но не начинать скачивание без подтверждения пользователя.

### 3.2. Поддержка ссылок

Реализовать систему обработчиков источников (Source Providers).

Каждый обработчик должен иметь единый интерфейс:
- validateUrl()
- getMetadata()
- getAvailableFormats()
- download()

Первая версия должна поддерживать:
- Прямые ссылки на MP4.
- Прямые ссылки на MOV.
- Другие разрешённые прямые видеоссылки, если формат поддерживается.

Для YouTube:
- Распознавать ссылки youtube.com и youtu.be.
- Открывать встроенный плеер и получать доступные MP4-дорожки на iPhone.
- Собирать видео и звук на устройстве, показывать доступные качества до 1080p.
- Сохранять возможность открыть видео на сайте и понятно сообщать об ограничениях источника.

Для VK Видео:
- Распознавать ссылки vkvideo.ru, vk.com и vk.ru на отдельные ролики.
- Получать публичные параметры основного плеера на устройстве, сверять owner/video ID и скачивать MP4 выбранного качества напрямую.

Архитектура должна позволять добавлять новые разрешённые источники без изменения основного интерфейса.

### 3.3. Выбор качества

Предусмотреть варианты:
- 360p.
- 480p.
- 720p.
- 1080p.
- Original.

Показывать только те варианты, которые действительно доступны у источника.

Не обещать 1080p, если источник не предоставляет такое качество.

### 3.4. Система загрузок

Реализовать:
- Отображение прогресса загрузки.
- Процент выполнения.
- Полученный объём данных.
- Общий размер файла, если известен.
- Скорость загрузки, если возможно определить.
- Отмену загрузки.
- Обработку ошибок.
- Повторную загрузку.
- Несколько задач в очереди.

Использовать нативные возможности iOS для загрузки файлов, где это возможно.

Учитывать ограничения фонового выполнения iOS. Не обещать бесконечную работу приложения в фоне.

### 3.5. Библиотека видео

Создать отдельный экран со скачанными видео.

Функциональность:
- Список видео.
- Название.
- Обложка, если доступна.
- Размер файла.
- Дата загрузки.
- Воспроизведение.
- Удаление.
- Экспорт через системное меню iOS.
- Сохранение в Photos при наличии разрешения.

### 3.6. История

Хранить историю загрузок локально через SQLite.

Статусы:
- Pending.
- Downloading.
- Completed.
- Failed.
- Cancelled.

Сохранять:
- URL источника.
- Название.
- Качество.
- Формат.
- Размер.
- Дату.
- Путь к локальному файлу.
- Статус.

### 3.7. Исключение рекламы при загрузке

Цель: не скачивать отдельный рекламный ролик вместо выбранного пользователем основного видео.

- До добавления в очередь каждый Source Provider должен проверять кандидатов на загрузку и исключать ресурсы, явно обозначенные источником как реклама: pre-roll, mid-roll, post-roll, ad creative и другие рекламные материалы.
- Использовать доступные метаданные источника, признаки рекламного плеера и точные правила для известных рекламных доменов и путей. Совпадение произвольной подстроки `ad` в URL, небольшая длительность или размер файла сами по себе не являются достаточным основанием для блокировки.
- Не выбирать первый найденный MP4/MOV: он может оказаться рекламным роликом. Выбирать основной контент по данным провайдера; при нескольких неоднозначных кандидатах показывать выбор с доступными названием, обложкой и длительностью. Без выбора пользователя загрузку не начинать.
- Проверять адреса перенаправлений до запроса рекламного ресурса. Если используемый механизм не позволяет проверить перенаправление до скачивания, не заявлять гарантированный пропуск рекламы для такого источника.
- Если обнаружена только реклама, не добавлять её в очередь и библиотеку. Показать: «Найден только рекламный ролик. Основное видео пока недоступно».
- Для прямого MP4/MOV без метаданных невозможно гарантированно определить рекламное назначение. Не объявлять такой файл проверенным на отсутствие рекламы; перед загрузкой показывать доступные сведения о файле.
- Если в будущем будет добавлена поддержка потоков с отдельно размеченными рекламными сегментами, пропускать их только при надёжной разметке провайдера и корректной сборке основного видео. До появления такой реализации не заявлять эту возможность поддерживаемой.
- Рекламу, уже вшитую в изображение и звук единого видеофайла, автоматически не вырезать. Не обещать её обнаружение или удаление.
- Проверка и исключение рекламы не должны обходить ограничения источников, DRM или авторизацию.

Критерии приёмки:
1. При наличии рекламного MP4 перед основным MP4 рекламный файл не попадает в очередь и библиотеку; выбирается основной ролик, подтверждённый данными провайдера.
2. Если источник возвращает только явно обозначенную рекламу, загрузка не начинается и отображается понятное сообщение.
3. Обычный короткий ролик и URL с буквами `ad` внутри обычного слова не блокируются только по этим признакам.
4. Неоднозначные кандидаты требуют выбора пользователя и не запускаются автоматически.
5. Перенаправление на известный рекламный ресурс блокируется до загрузки его тела у провайдеров, поддерживающих проверку перенаправлений.

## 9. Критерии готовности MVP

Приложение считается готовым, если:

1. Запускается на iPhone.
2. Позволяет вставить прямую видеоссылку.
3. Определяет доступный формат.
4. Скачивает поддерживаемое видео.
5. Отображает прогресс.
6. Позволяет отменить загрузку.
7. Сохраняет файл локально.
8. Позволяет воспроизвести и экспортировать видео.
9. Сохраняет историю после перезапуска.
10. Корректно сообщает об ошибках и неподдерживаемых источниках.
11. Исключает явно распознанные рекламные ролики и не скачивает неоднозначный кандидат автоматически согласно разделу 3.7.

Сначала реализовать полностью работающий MVP. Не добавлять фиктивные функции и не имитировать поддержку источников, которые фактически не работают.
